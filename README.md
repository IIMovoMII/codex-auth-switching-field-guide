## 这是什么

这不是下载后就能运行的切换软件，而是**给编程智能体使用的产品说明书和实战经验包**。

把下面一句话交给 Codex，它会先了解你的电脑和需求，再据此编写适合你的脚本或小应用。你可以只做“官方 ↔ 中转”，也可以增加多个官方账号、多个中转站和各自的模型设置，不必照搬作者的电脑环境。

## 适合谁

- 平时用中转 API，偶尔切回官方账号，不想来回改配置。
- 经常更新插件、MCP、Skills 或钩子，担心切换后设置被旧配置覆盖。
- 想在两种模式下继续同一个本地对话，而不是每次重开。
- 不同中转站的模型、思考档位和代理要求不同，需要分别保存。
- 用其他切换工具改坏过配置，希望有能离线使用的恢复办法。

## 一句话部署

复制给编程智能体：

~~~text
请阅读 https://github.com/IIMovoMII/codex-auth-switching-field-guide，从 SKILL.md 开始，结合我的电脑环境和实际需求，为我构建并验证 Codex 账号与接口切换工具。
~~~

智能体应先读取能自行确认的信息，只询问需要你决定的部分。**需要登录、输入密钥、关闭 Codex 或修改历史时，会说明原因；不会凭空生成登录态。**

## 你可以得到什么

| 功能 | 实际作用 |
| --- | --- |
| 一键切换 | 一个入口串起必要检查、历史准备和账号切换；高级修复选项另外保留 |
| 保留持续更新的配置 | 每次基于当前配置修改，不拿两份旧配置来回覆盖 |
| 旧对话兼容处理 | 分别检查会话归属、模型输入和界面索引；能安全修复才处理 |
| 多账号、多中转（可选） | 每个档案保存自己的凭据、模型和思考档位，不复制整份配置 |
| 首次使用引导 | 缺少官方登录态就引导 OAuth；缺少 API 配置就引导本地录入 |
| 出错可恢复 | 区分登录失败、配置损坏和历史异常，不靠反复点击碰运气 |

这些是可选的产品能力，不代表本仓库已经附带了安装器或实现代码。

## “不丢聊天记录”具体指什么

目标是保留本地对话的正文、工具结果、项目归属，以及原任务打开和继续对话的能力。

但**能看到旧消息，不等于模型能接受全部旧输入**。有些中转会返回官方接口不接受的编号或推理数据。修复时应保留可见历史，说明哪些模型输入不能继续使用，并保留恢复材料；不能为了让扫描显示“零问题”直接删聊天。

验收要同时看三件事：**旧内容看得见、模型接得上、新消息能继续保存和显示。** 这不是对未来所有 Codex 版本、账号和中转站的永久保证。

## 为什么有时切换慢

通常慢在历史检查，不是换密钥。历史没有变化时可以走快速检查；中转产生了新记录、Codex 更新或修复规则变化后，可能需要重新准备。

一次排查发现，慢的是脚本逐字节解码大量历史文本，而不是必须多等几分钟。经验包要求先测各阶段耗时，再优化瓶颈，不能靠跳过检查提速。首次初始化和日常切换也应分别显示进度。

## 首次使用与故障恢复

没有官方账号的本机登录记录也能开始，但第一次仍需要你亲自登录。配置写好后，有些检查必须等完全重启 Codex 才能做；工具应记住进度，告诉你下一步，而不是提前报“全部完成”。

如果已有 CC Switch 等工具管理同一份配置，先选择由谁负责，避免互相覆盖。配置被清空、只剩通用模板或 Codex 已无法对话时，可用一份已知良好配置回滚；没有备份则根据可信信息重建。详见[首次使用](references/first-use-bootstrap.md)和[配置恢复](references/config-recovery.md)。

## 适用范围与验证边界

实战证据主要来自 Windows；macOS、Linux 可以按本机机制适配，**不代表三平台已有现成成品或全部实测**。

本次经验包含原生 Codex CLI 0.159.2 的分页历史副本验证、后续 0.162.0-alpha.2 隔离副本对“只有合法编号、没有可重放内容”的复核、真实切换后的逐条内容核对，以及 PowerShell 5.1／7 的回归测试。具体检查、未覆盖项和性能证据见[验证清单](references/validation.md)。首页的绿色检查只证明文档结构、链接和有限隐私规则通过，不证明你的电脑部署成功。
