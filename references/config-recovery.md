# 配置恢复与外部写入者

[English](config-recovery.en.md)

config.toml 被清空、变成通用模板或语法损坏后，Codex 可能连对话都无法开始。恢复入口因此不能依赖一个正常工作的 Codex 会话。

## CC Switch 的证据边界

曾有切换后配置不完整、Codex 无法对话的事件，但没有保存损坏前后文件和确切版本，不能认定每个 CC Switch 版本都会损坏配置，也不能编造该事故的精确根因。

曾检查的源码版本 9a596158ca926e74b56243c08af67d9dd13fc27c 使用数据库／档案管理配置并向实时文件写入目标文本，可参考[配置模型](https://github.com/farion1231/cc-switch/blob/9a596158ca926e74b56243c08af67d9dd13fc27c/docs/user-manual/zh/5-faq/5.1-config-files.md#L295-L322)、[切换流程](https://github.com/farion1231/cc-switch/blob/9a596158ca926e74b56243c08af67d9dd13fc27c/src-tauri/src/services/provider/mod.rs#L4931-L4942)和[写入路径](https://github.com/farion1231/cc-switch/blob/9a596158ca926e74b56243c08af67d9dd13fc27c/src-tauri/src/codex_config.rs#L864-L880)。这是固定修订的设计证据，不是对今天最新版的评测。

自建切换器以实时配置为准。如果另一管理器也投射保存的完整配置，两者可能覆盖彼此新增的字段。默认由用户选择一个路由管理器；没有经过测试的协调机制时，不交替管理同一文件。不必卸载工具的其他功能。

## 先停，再恢复

发现空文件、解析失败、字段突然消失、provider 不存在或切换后立即无法请求时，停止写入者和重复切换。检查层级覆盖与实际认证；不要仅凭文件变小就断定损坏。

提醒用户私下保留一份已知良好的完整配置，存放在公开仓库和外部工具控制范围之外。它不能代替认证快照，也不证明旧登录态仍有效。需要定位事故时，另存坏文件必须由用户选择，不无限累积备份。

## 有已知良好配置时

1. 停止 Desktop、CLI 和所有相关配置管理器。
2. 核对恢复点版本、文件哈希和字段结构，确认当前认证类别，不打印秘密。
3. 恢复完整结构，再只调整与当前目标相符的路由／模型／代理字段。
4. 官方 OAuth 模式移除中转覆盖；中转模式使用该档案的地址、API 凭据和受支持模型。恢复配置不会自动转换认证。
5. 暂存解析通过后写回，确认非自管配置仍在。
6. 新进程验证真实请求与关键扩展；旧任务续聊另需历史门禁。

本指南经过目标版本验证的共同结构是 model_provider = "openai"，中转另有顶层 openai_base_url；不要把示例的几行当作整份配置覆盖回去。缺失 provider 定义先修配置，不要先删除 auth 或历史。

## 完全没有可用配置时

无法凭空恢复丢失的值，只能重建：

- 从当前版本支持的最小配置和实际认证开始，不猜秘密。
- 从可信本地项目记录、扩展清单、钩子文件和用户确认中逐项找回设置。
- 每个子系统单独验证；需要启动时读取的内容用新进程确认。
- 先测可丢弃的新任务，再在历史门禁通过后测旧任务。
- Codex 无法工作时，可使用本机命令行或另一个编程智能体（例如 Claude）检查脱敏结构。
- 明确区分“从证据恢复”“用户补充”“新建”和“仍未知”。

先验证再将结果替换为新的已知良好恢复点。不要用看起来整洁的通用模板掩盖实际丢失的能力。

## 切换器可提供的修复入口

按需求实现只读配置检查、选择恢复点、引导重新认证、更新中转地址／模型和恢复未完成事务。恢复不是自动猜值：要显示范围和结果，尊重用户后续编辑。普通一键切换不应悄悄执行灾难恢复。
