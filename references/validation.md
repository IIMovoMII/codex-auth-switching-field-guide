# 验证与证据边界

[English](validation.en.md)

按用户选择的功能验证，不把建议清单写成“全部已经实测”。本仓库没有切换器程序，下面分为复现经验和未来实现的验收标准。

环境：Windows，原生 Codex CLI 0.159.2；本地脚本兼容 PowerShell 7 和 Windows PowerShell 5.1。记录于 2026-10-01，不代表未来版本或其他操作系统通过。

| 检查 | 已得到的证据 | 边界 |
| --- | --- | --- |
| 真实切换后的内容 | 已检查修复清单和原文件备份：80 项编号改名、0 项删除；非目标行逐字节相同，目标行只变指定 ID，数据库完整性通过 | 证明这一次被记录的修改；不是全部历史跨全部接口的保证 |
| 分页与续段 | 原生客户端在隔离副本中读取旧界面历史，并索引追加的合成事件；继承历史仍可显示 | 测试不携带凭据、不发模型请求，不能替代官方续聊验收 |

| 中文与兼容性 | 两代 PowerShell 的中文输出、代理切换、历史修复和解码测试通过 | 不是三平台成品测试 |

此前实际事务记录的约 29 秒仅涵盖备份、修改和复查，不包含前面的扫描与规划。因此不能拿它否定用户看到的几分钟等待。性能优化必须复测同一项，且不能把失败判断改成放行来制造加速。

这些本机测试与隐私数据不随仓库分发。可复用的是判断方法、边界和以下测试设计；不要把表格当成你本机部署的通过证书。

## 实现时的最低验收

| 场景 | 应验证的结果 |
| --- | --- |
| 配置保留 | 含插件、MCP、Skills、钩子、权限、项目、注释和未知字段的合成配置，切换前后只有自管字段变化；中间新加的设置仍保留 |
| 模型／档位 | 精确组合受目标支持；不悄悄降档。若不由切换器管理，原值保持 |
| 缺少登录态 | 只有官方、只有 API、两者皆无和未完成初始化都有明确下一步；取消不覆盖有效源档案 |
| 认证失败 | 本地类型检查、真实请求和令牌刷新分别测试，失败状态不标为就绪 |
| 配置损坏 | 空文件、无效 TOML、模板化、缺失字段和外部并发修改被识别；有备份／无备份分别恢复 |
| 一键入口 | 未初始化、准备有效、准备过期、准备失败均可收敛；历史失败在认证切换之前 |
| 日志与容量 | 脱敏错误、阶段耗时、有限保留；磁盘不足在破坏唯一恢复材料之前停止 |
| 版本更新 | 新版本相关行为经核对仍兼容时可复用原实现；同表结构但读取语义变化的案例不能误放行；证据不足时阻止依赖它的写入与切换 |
| 多官方账号 | 每个账号分别验证旧任务可见、可打开、模型续聊和新消息索引；不能用账号 A 的成功替代账号 B |

## 历史夹具

合成用例至少覆盖所支持布局的这些边界：

- 当前／归档、两种 provider 语义字段、多个 WAL 数据库、云端样例行隔离；
- 旧 provider 较短、较长及等长；分页空间不足拒绝；
- 正确、通用和超长 ID；目标协议长度边界；重复编号与未知类型；
- reasoning 受保护内容、独立可见事件、工具调用／结果配对；
- 合法前缀但只有 ID／空白摘要的 reasoning、没有模型投影行的旧分段，以及轮次引用时拒绝；
- 合法 ID 与完整加密内容在原生预热后续传仍失败的请求；修复只改变指定旧模型 ID，保留工具关联、守护历史、界面编号和新生成的 ID；
- 直接模型投影与独立事件投影、逻辑 ID 与存储分段 ID；
- 空投影与悬空引用、复制父元数据的物化分支，以及原备份／旧清单能证明的布局恢复和证据不足时拒绝；
- 非零继承基线、缺段、异常 ordinal／字节游标、未完成索引；
- 修复后追加新事件、重新打开、重复回滚、回滚遇到新活动；
- 规则升级、相关库变动、无关日志变动与准备记录损坏。

旧内容、模型续聊、新消息索引三项都要验收。原生无网络副本测试只覆盖其中的显示与索引；真实模型请求必须单独记录，不能只写“扫描为零”。

## 故障与升级

对实际实现注入相应风险：并发切换、文件占用、写入拒绝、空间不足、快照不可读、写入中途退出、回滚失败、用户在阶段间修改配置。结果应是已恢复、已验证目标、待重启／登录，或有明确恢复入口的未知状态，不能含糊称“部分成功”。

中断测试要覆盖“文件已替换、清单尚未更新”和“部分文件已应用、数据库尚未处理”等阶段，并重新启动入口验证它先处理未完成事务。手工回滚命令或正常异常测试通过不能代替这项。未经真实强杀测试，不宣称相应恢复能力；断电与存储硬件故障另列限度。

Codex 更新后重新核对配置、认证、历史布局和传输。未完成适配时保留原数据并禁用未经验证的历史写入；不要把旧准备记录的数字手改大。升级检测可以轻量执行，耗时探针按失效原因运行，不必每次重复全部网络和历史测试。

组件测试分别覆盖切换协调／恢复和版本相关的配置／认证／历史／传输；另保留一键入口的集成测试，确保任何必要准备失败都不会启用目标认证。几个模块并不代替整条流程的验证。

若实现检查缓存，验证未变历史、无关日志和菜单变更不触发完整准备，相关行为／规则变化会失效；验证截断／重写／移动、归档和父段／数据库变化能使依赖结果失效。增量结果与同一快照的完整检查应一致。按实际数据规模报告快慢路径耗时与读取范围，缓存能力和性能数字未实测时标为设计，不能宣传成已有功能。

## 仓库自带检查的边界

运行 python scripts/validate_pack.py 检查必要文件、相对链接、双语引用覆盖和有限秘密模式；Skill 快速校验只检查入口格式。它们不执行 OAuth、状态机、SQLite 事务、模型请求或 Windows 故障注入，也不证明中英文语义完全一致。发布前仍需人工审查逻辑、证据和隐私。
