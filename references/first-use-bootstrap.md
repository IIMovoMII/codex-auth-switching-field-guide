# 首次使用与重启检查点

[English](first-use-bootstrap.en.md)

首次使用可能跨越人工登录和多次进程重启。不要把“已保存配置”标成“档案已可用”，也不要要求每台电脑机械执行相同次数的重启。

## 根据起点继续

| 起点 | 下一步 | 未成功时 |
| --- | --- | --- |
| 只有官方登录态 | 保护当前状态，引导添加 API 档案 | 官方状态不被丢弃 |
| 只有 API 状态 | 保护当前状态，引导官方 OAuth | 可以恢复 API |
| 两种都已实测 | 走日常切换 | 按事务恢复 |
| 两种都没有 | 询问先建立哪种，再走原生登录／本地录入 | 保持未初始化 |
| 有快照但未验收 | 从检查点继续 | 不冒充已就绪 |
| 来源不明、路线与认证冲突 | 先诊断，不覆盖快照 | 明确需要处理的冲突 |

直接 OpenAI API Key 可以是合法的第三种模式；若本次只做官方 OAuth 与中转，应说明暂不支持，而不是误报认证损坏。判断凭据有效性要区分“本地类型可读”和“真实请求成功”。

## 没有官方登录态

先保护已经工作的状态，准备官方路线并移除中转地址及其他生效覆盖，再让用户通过当前版本支持的官方登录流程完成 OAuth。不要把官方 OAuth 凭据发给中转地址。

新凭据必须确实由登录产生；空 auth.json 或示例令牌不是档案。确认新进程加载了预期账号／路线并完成最小真实请求后，再把官方档案标为可用。需要捕获快照时，确保写入者已停止且刷新后的认证稳定。

用户取消或登录失败：保留原档案并提供恢复；需要再次登录的目标保持未完成，不覆盖先前有效快照。

## 没有 API／中转配置

只询问无法读取的非秘密意图：供应商、地址、想用的模型和思考档位。传输能力应尽量自行探测，不要求用户懂协议名称。

密钥通过本地遮罩输入或系统凭据界面获取，不进入聊天。验证地址、当前版本的配置表达和目标模型，再事务启用路线与认证。新进程请求失败时不要保存为“已验证”；保留回滚入口。模型或档位不可用，提示用户选择，不静默降低。

## 首次历史准备

用户要保留旧任务跨模式续聊时，先验证共同 provider 结构，再停写扫描和准备。可以由同一个首次切换入口自动串联，不必要求手工运行多条命令。处理未知分页布局或不可恢复模型输入时，按[历史兼容](history-compatibility.md)说明影响或停止，不能提前启用目标认证。

## 可恢复的进度

保存非秘密检查点：流程版本、源／目标档案编号、阶段、修改前指纹、事务引用、重启后预期、下一步用户动作及已验证的客户端版本。不要把凭据或正文放在进度提示中。

可用阶段：

~~~text
源状态已保护 → 目标待登录／录入 → 已暂存 → 待重启验证
                                      → 已验证可用
                                      → 需继续／需回滚
~~~

每次进入先检查当前实际状态，重复点击不重复覆盖。要求关闭 Codex 前明确告诉用户如何继续；部署了提醒器时可在其支持的机制下登记有期限的计划维护，不能无期限屏蔽错误。

涉及启动时读取的配置，必须用全新进程确认。未完成重启验收时可以交付工具和下一步，但不能把全部功能标为已实测。取消流程只清理确认属于本次的临时档案；已存在的凭据和新产生的用户数据不得顺手删除。
