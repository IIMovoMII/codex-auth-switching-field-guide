# 网络诊断

[English](network-diagnostics.en.md)

“重新连接 5/5”不是一种唯一故障。先看脱敏错误、失败路径和阶段，再决定是网络、认证、模型还是历史问题，不因同一界面提示套用旧结论。

| 现象 | 优先核对 |
| --- | --- |
| 超时、断流 | DNS／TLS、代理、连接复用和服务端状态 |
| 404 | 实际地址拼接和具体接口路径；不能仅凭一次响应判断所有能力 |
| 401／403 | 认证类别、有效期、权限及目标路线 |
| 模型或档位不可用 | 精确模型编号与档位组合、供应商能力、界面缓存 |
| 新旧任务各自第一轮慢，随后正常 | 是否发生传输初始化、WebSocket 重试与 HTTPS 回退 |
| 官方模式仍请求中转 | 生效配置、档案、环境变量或启动参数残留覆盖 |
| 400 指向旧输入的 ID／reasoning | 检查历史协议兼容；不要只折腾代理 |

## HTTPS 与 WebSocket 分别验证

支持 Responses HTTPS 不代表支持 WebSocket 升级。检查准确的路径、认证方式、必要头部、代理是否传递升级，以及客户端是否回退。

“5/5”本身不证明固定进行了五次 WebSocket 调用；需要当前版本日志支持。不能把中转必须支持 WebSocket 写成所有版本的硬条件：若客户端支持 HTTPS 回退，中转仍可能可用但首次有延迟。

只有当前版本确认支持并实测有效时，才能让档案管理传输关闭或选择字段。不要添加网上找到但本版本忽略的配置，随后宣布问题解决。缺少可用开关时如实说明限制，不通过修改历史掩盖网络失败。

## 代理不只是一行开关

“VPN 全局”不等于 Codex 实际请求按预期出站。区分系统代理、进程代理环境、TUN、绕过规则、DNS 和 WebSocket 路径。浏览器能访问不能替代客户端探针。

respect_system_proxy 等字段需按版本核实，用新启动的进程验证。设置 false 只是在支持该字段的实现中不主动跟随系统代理，不能绕过操作系统 TUN 或强制保证直连。两种档案可以有不同策略，不能替每个用户固定官方必开、中转必关。

## 最小检查与收尾

先做不带凭据的 DNS／TLS 和地址检查，再在授权范围内进行最小认证、模型和必要的传输探针；匹配 Codex 实际启动环境。不得为了探针把官方 OAuth 发到非官方地址，也不记录认证头、请求正文或带秘密的查询参数。

修正路线后重启并复测；认证失败走重新登录；模型不支持让用户选择；无法消除的回退说明成本。503 等供应商错误只做有界重试，不能据此改历史或不断切换账号。原因未明时保留最后可用档案，列明已验证层和下一项检查。
