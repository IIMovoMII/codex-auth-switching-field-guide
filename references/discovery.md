# 环境盘点

[English](discovery.en.md)

只读盘点先于实现。输出脱敏结论，不转储配置、认证或真实对话。

## 自行读取的事实

- 系统、Desktop 和 CLI 的实际版本、可执行文件、状态目录；两者未必使用同一版本或同一个 CODEX_HOME。
- 活跃写入者、外部配置管理器及未完成事务。可见窗口关闭不等于进程退出；应用合并或改名后不能只按固定进程名判断。
- 生效配置及覆盖来源：用户级、项目级、原生档案、命令行与环境变量。层级能力以安装版本为准，文件出现的值不一定生效。
- 路线、模型、思考档位、传输和代理；插件、MCP、Skills、钩子、权限及项目项的存放方式。
- 认证类别与存储位置：OAuth、API Key、缺失或不可读取；不得输出令牌或凭据值。
- 当前及归档 JSONL、SQLite 表结构、WAL、分页／分段／继承历史和云端记录边界。
- 已有受保护快照、最后验证结果，以及是否有可用恢复材料。

路径对公开报告通用化。检查模型菜单是否来自本机缓存、服务返回或档案配置；菜单显示不等于目标端点接受该模型与档位。

## 接口探针

分开检查地址拼接、TLS、认证、HTTPS Responses、可选的 WebSocket、精确模型与思考档位。使用最小非敏感请求；真实请求可能计费，应在用户接受的范围内执行。日志只保留状态类别和耗时。

401 不证明 provider 名称错误，404 不一定证明所有 WebSocket 都不支持，浏览器可用也不证明 Codex 继承了同一个代理。详细诊断见[网络诊断](network-diagnostics.md)。

共同 openai 身份需要分别验证官方路线和中转地址覆盖，并查看新任务记录。还没有另一种登录态时标为待验证，先引导初始化；不要伪造双向验证来满足门禁。

## 只询问真正的选择

集中询问缺失且影响实现的事项：

- 只做两模式还是多个账号／中转？
- 旧任务必须跨所有档案续聊吗？不能安全转换时接受什么处理？
- 想用命令行、小窗口还是现成系统入口？
- 模型／思考档位是否跟档案切换，还是保持当前设置？
- 可以何时关闭 Codex？备份空间和保留策略如何取舍？
- 由哪个工具管理路由，是否需要迁移既有档案？

用户已说过的偏好不重复问。不要把可读的系统、目录和版本变成问卷，也不要要求用户在聊天中贴完整 config 或 auth 文件。

## 盘点结果

给出当前状态、所选范围、缺少的凭据、需要停机的动作、历史布局和待验证项。若有冲突，先定位再设计写入；正常的未知项应有下一步探针，不要一律判坏。
