# 空界面子代理终态：不要把正常中断误判成来源不明

[English](empty-subagent-projection.en.md)

记录于 2026-10-23。这是脱敏的实现经验，不包含本机任务编号、聊天正文、认证或可直接运行的修复程序。

## 表面症状

切换前的历史准备报错：

~~~text
模型编号与界面索引未证实独立，拒绝清除
~~~

这类拒绝本来是安全的：模型 `response_item` 的编号不能因为看起来可选，就直接从 JSONL 清掉；必须先证明界面索引来自独立事件，并且没有轮次引用会被留下悬空。但一次真实记录说明，原生子代理也可能在产生第一条界面项目之前就被中断，于是本来没有可验证的界面行，严格检查反而把正常布局误当成未知布局。

## 根因

旧判断只接纳了“失败轮次 + `task_complete`”这一种空投影终态。真实原生布局是：

- `session_meta` 明确是分页子代理，父线程、子代理路径和收件对象一致；
- `thread_items` 对该线程为空，`thread_turns` 没有首条用户项目或最终代理项目引用；
- 轮次状态是 `interrupted`，最后事件是 `turn_aborted`，原因为 `interrupted`；
- JSONL ordinal 从零连续，任务起始字节位置、文件末尾、SQLite 游标完全一致；
- 除系统／开发者／用户输入和代理间消息外，没有 assistant 输出、未知事件或工具配对需要改动。

因此它不是“任意空表都安全”，而是“有完整终止证据、但尚未产生界面投影”的特殊布局。`failed + task_complete(error)` 和 `interrupted + turn_aborted(reason=interrupted)` 是两个独立、都需要逐字段核对的终态；不能只把状态判断改成“不是进行中”。

## 可接受的修复边界

只有在上述证据全部成立时，才允许沿用已经在当前客户端副本验证过的规则，清除模型输入中明确可省略的旧 ID 固定槽位。修复必须：

- 保留正文、工具关联、`call_id`、加密内容、ordinal、行数和字节边界；
- 不删除或改写界面事件，不补造界面项目，不写 `thread_items` 或 `thread_turns`；
- 不改当前轮次的新 ID，不改父线程，不改分页游标；
- 先做可恢复记录，失败时只撤销本次清单中的等长修改；
- 任何状态／原因／父线程／收件路径／游标不一致都停止，不用“自动修复”绕过门禁。

如果记录已经有界面行、轮次引用、assistant 输出、未知事件或未结束状态，就不能套用这条经验，必须回到一般的事件来源核对。

## 验证方式

先在不含认证的副本验证：正反例至少覆盖 `failed`、`interrupted`、错误中断原因、错误轮次／根轮次、非子代理、界面行存在、CRLF、增量追加和精确回滚。再用一条脱敏的真实记录副本核对字段、字节边界、数据库不变和回滚。最后才在完全停机的本机历史上执行，并分别验收旧内容、模型续聊和新消息索引。

这次实现的回归包括 PowerShell 7／5.1 的 23 个正反案例，以及 79 个历史文件和 3 个相关数据库的临时副本演练；这些数字只说明该次布局的证据，不是未来 Codex 版本的通用保证。

## 给实现者的结论

“准备失败就不切换”仍然是正确原则。正确的改法是补上已证明的终态，而不是删除“界面来源未证实”的拒绝条件。把终态识别、事件来源证明、模型输入清理和账号启用分开；未知格式继续停在认证切换之前。
