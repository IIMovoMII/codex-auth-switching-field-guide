# 增量准备：提速，但不缩小兼容检查范围

[English](incremental-preparation.en.md)

2026-10-14 的本机实现经验，整理于 2026-10-18。这是供智能体选择的实现路线，不提供可直接运行的迁移程序。先理解[历史兼容](history-compatibility.md)中的语义、分页和继承边界；数据很少时，简单的完整检查也可以更合适。

## 为什么要分成两层记录

最终的“可以切换”记录，绑定本次历史清单、相关数据库、目标协议、修复规则和检查缓存。聊天继续写入后，这份结论应过期；但这不等于每个旧文件都要重新解析。

另一层逐文件记录保存已经验证的干净范围：路径和稳定文件身份、长度／修改时间、完整前缀哈希、完整行边界、最后 ordinal、线程归属、布局与规则指纹，以及适用时的界面来源证据。缓存要有完整性校验和明确版本。缺字段或校验失败不能当作空历史或准备成功。

本机最终准备记录仍为版本 3，并新增绑定检查缓存哈希；逐文件缓存使用自己的版本。这只是本机格式，不要求其他实现沿用数字，更不能手工提高旧记录版本号。

## 同一次准备中的分流

| 变化 | 已验证路线 |
| --- | --- |
| 干净文件身份、大小、时间及适用规则未变 | 复用该文件的检查结果，不重新解析正文 |
| 已验证分页文件只增长 | 核对整个旧前缀哈希；旧尾、新尾都是完整行且无新增会话元数据时，只解析追加部分 |
| 新文件、旧前缀不匹配、重写／截短／替换、移动／归档、新增元数据 | 重新完整检查受影响文件及依赖；移动不自动等于损坏 |
| 发生变化的旧式非分页格式 | 保留完整检查，不能假设其语义只依赖新增行 |
| 缓存损坏、相关规则或历史库结构变化 | 放弃旧逐文件记录，重新建立完整基线；仍无法确认时停止 |
| 只有数据库内容变化 | 实时检查有关 provider、界面来源、轮次、游标及继承依赖，不因 JSONL 未变而跳过 |

这里只是变化检测路线，不是通用语义白名单。父段、继承基线或关联行变化时，要重新检查依赖它们的结果。不能仅凭文件变长、尾部几个采样哈希或缓存中没有问题，就认定是纯追加。

**只解析新增行，不等于只从磁盘读取新增行。** 本机追加路径仍读取整个旧前缀来计算哈希，写前和恢复也可能核对全文件。没有变化的文件以身份／大小／时间等检测正常改动，这不是对恶意保持元数据篡改的安全保证。

## 界面索引不能靠正文缓存代替

正文前缀不变，数据库旧界面行仍可能变化。本机 PowerShell 7 路径只有在旧相关投影字段、轮次等指纹仍匹配时，复用旧来源证明并验证新增来源；不匹配就完整核对受影响文件。PowerShell 5.1 保留完整界面来源检查，因此两者速度可能不同。

SQLite 的 provider 行仍实时读取；格式发现不能只看固定文件名。数据库结构变化可让所有逐文件证据失效，内容变化则触发相关重查；最终准备记录还要绑定数据库及 WAL 状态。不要把数据库查询时间藏在“只读几行”的宣传里。

## 小修改可以用小备份，但要有明确适用条件

本机仅对已验证分页文件的新增记录、且动作仅为清理允许省略的旧模型输入 ID 时使用固定字节槽位：

1. 记录精确偏移、旧／新字节和完整文件身份、长度、原始／预期哈希；小备份、校验和与事务清单先持久化。
2. 在同一个独占文件句柄内再次核对身份和归一化完整哈希，再将 ID 写成 `null`，余下字节留空格，刷新落盘。
3. 验证实际输出、语义和投影未被意外改变，之后才能保存新的检查结果与最终准备记录。

归一化哈希指在已登记槽位虚拟代入旧值／目标值后核对整个文件，不是只检查被改的几处。恢复可接纳槽位内由旧／新字节组成的已验证半途写入，但槽位外改动、后续追加、长度变化或文件替换都会拒绝覆盖。

只涉及 `response_item.payload.id`、`compacted.payload.replacement_history[*].id` 中经当前规则证明可省略的旧模型 ID；不改正文、工具配对、`call_id`、加密内容、界面事件、守护记录或本轮新编号。首次全量、provider 迁移、不可重放推理占位及布局恢复仍走各自已验证的完整备份路径。小备份不能推广为任意修复都安全。

## 下一次启动先恢复，不能把半成品当干净历史

写前保存未完成事务标记，并在最终就绪检查中阻止它放行。再次进入停机准备时，先读取对应清单，核对并撤回可确认的未完成修改，再重新准备；不能先创建新计划覆盖旧证据。小槽位备份和 SQLite 事务分别恢复，跨文件不是一个原子事务。

材料缺失、校验失败、路径越界或后来数据变化时保留材料，进入明确的人工恢复状态。详见[安全与回滚](safety-and-rollback.md)。本机验证的是模拟半途写入、槽位撕裂及持久标记后的再次进入；不是实际断电、所有强杀位置或所有旧格式的恢复认证。

## 保留完整检查、可解释耗时和小体量

- 日常一个入口串起必要阶段；保留显式强制完整检查与只读扫描。强制完整时不能又被“准备仍有效”短路。
- 无变化检查不产生新历史备份；单份缓存、最近失败摘要和最近耗时报告覆盖更新。实际恢复材料按约定有限保留，不能删除未完成事务的唯一依据。
- 分别统计跳过／追加／完整检查文件数、解析字节、前缀核对字节、分页核对、备份修改和认证阶段；总时间包含首次登录等待。可选耗时日志写失败只能警告，不能把已完成的认证切换误报成失败；必要事务清单则必须可靠写入。
- 最近失败摘要可能来自旧运行，不是实时健康状态；结合时间、本次阶段和当前实际模式判断，不能见到旧错误文件就自动修历史。
- 不需要常驻扫描器。把规则、增量缓存与主切换流程分开维护，用本地源码版本和简短更新记录解释变更；凭据、配置、聊天、数据库、备份和运行输出不进入源码 Git。

副本结果：约 3.8 GB／349 文件的首次准备约 74 秒，后续无变化约 1.83 秒；两轮合成追加各解析 234 字节、跳过 348 个旧文件，准备约 4.65／4.60 秒，但每轮仍核对约 23.4 MB 旧前缀。它们不是实际账号切换总时间。逐行内容、数据库未变及精确回滚检查与未覆盖项见[验证清单](validation.md)。
