# 可选的多账号、多中转档案

[English](multi-relay-profiles.en.md)

只在用户需要时实现；单中转两模式无需变成复杂的账号管理器。本模块是其他使用者可以加入的设计，不代表作者本机已实现全部功能。

## 每份档案保存意图

| 字段 | 含义 |
| --- | --- |
| 稳定编号、显示名、认证类型 | 供人选择；名称不是凭据 |
| 接口地址 | 官方 OAuth 无中转覆盖；API 档案对应自己的地址 |
| 受保护凭据引用 | 指向本机安全存储，不是密钥明文 |
| 模型与思考档位 | 用户选择的组合，或明确“保留当前值”的策略 |
| 代理／传输策略 | 当前系统和客户端实测支持的字段 |
| 验证信息 | 客户端版本、能力、时间及尚未通过的检查 |

不复制整份 config。切换时仍从实时配置读取插件、MCP、Skills、钩子和项目等共用内容。

## 模型不同怎么办

模型和思考档位是组合能力，不能只看供应商声明“支持模型”。分别验证精确模型编号、档位参数和目标接口实际接受情况。菜单缓存可能与运行配置不同，也不能证明 max 等档位一定可用。

用户明确选择按档案管理时，切换事务同时处理模型与档位。用户要求保留当前值时，先确认目标支持，不支持就让其选择；不得静默从 max 降到 xhigh、替换模型或把不同别名当作同一产品。候选列表是供用户选，不是自动降级授权。

## 生命周期

- **添加官方账号**：保护当前状态，走官方原生 OAuth，完成新进程验证后保存。账号标识只在本机按必要程度显示。
- **添加中转**：收集非秘密信息、本地输入密钥，验证真实请求；失败保持未就绪。
- **更新**：地址、凭据、模型或代理修改先暂存，失败可以恢复，不直接覆盖最后可用状态。
- **重新登录**：过期或刷新失败只影响相关档案，不删除其他账号。
- **删除**：先确认不是当前档案，也没有未完成事务依赖；明确凭据是否一并删除。
- **取消／中断**：从检查点继续或恢复；不覆盖用户后来写入的配置。

新增流程见[首次使用](first-use-bootstrap.md)，存储和恢复见[安全与回滚](safety-and-rollback.md)。

## 日常切换

在已证明共同 provider 的版本上，两种官方账号都用 openai 和各自 OAuth；中转 A／B 同样用 openai，但有各自地址、凭据和模型策略。

一个入口可完成状态检查、必要历史准备和目标切换。历史有变化时显示原因和进度；准备失败则保留当前认证。高级菜单再提供添加、更新、诊断和恢复，不让用户每次手工跑整套流程。

CC Switch 不是必需依赖。若自行管理档案，可让它停止写本套 Codex 配置；其他用途不需要卸载。不能让两个未协调的管理器互相覆盖实时文件。

多官方档案要独立验收 A→B→A，核对账号／工作区身份、各档案刷新后的凭据归属，以及原任务可见、可打开、可续聊、新消息可索引。本仓库没有完成双官方账号实测；不能从一次中转→官方成功推导出跨账号通用，也不能把跨账号推理项目必然失效当作已证实事实。

本地任务文件、界面索引、云端 Chat／Work 是不同数据来源。统一 provider 不会迁移云端账号权限。消息暂时不可见时先核对目录、项目、归档／筛选和当前账号，不删除索引或文件来“同步”。共用本地历史或隔离目录应由需求决定；独立 CODEX_HOME 会隔离本地文件，也不等于 Desktop 的全部登录状态和云端缓存都隔离，需要验证实际启动机制。
